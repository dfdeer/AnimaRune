# 앱 출시(애플리케이션화) 논의 정리

인수인계 목록에서 "병합 후 이어서 논의할 것" 1번이 출시야. 목표는 **파일 하나를 주면서 "이거 다운해"** 하는 방식이고, **폰과 컴퓨터 둘 다** 설치할 수 있어야 해.
이 문서는 결정용 자료야. 아직 아무것도 만들지 않았어.

## 1. 지금 구조 (코드로 확인한 것)

| 항목 | 지금 |
|---|---|
| 배포 | GitHub Pages — `https://dfdeer.github.io/AnimaRune/` (README.txt, docs/계정연동_설정.md) |
| 형태 | PWA: `index.html` 한 파일 + `sw.js`(오프라인 캐시) + `manifest.webmanifest`(standalone, 세로) |
| 세이브 | 기기 안 `localStorage` · 설정에서 세이브 내보내기/불러오기 |
| 서버 | Firebase — 익명 로그인 + 구글 계정 연결(`linkWithPopup`, 막히면 `linkWithRedirect`) · Realtime Database(레이드·친구·결투·문의·서버 세이브) |
| 허용 도메인 | Firebase 로그인 승인 도메인에 `dfdeer.github.io` |

→ 게임은 이미 **웹앱이라서, 어떤 방법이든 "이 웹앱을 무엇으로 감싸느냐"**의 문제야.

## 2. 방법 후보

### A. PWA 설치 강화 (지금 방식 개선)
- 게임 안에 **"앱으로 설치" 버튼**을 넣음. 안드로이드 크롬·PC 크롬/엣지는 버튼 한 번으로 설치 창이 뜸(`beforeinstallprompt`).
- 아이폰은 버튼으로 못 띄움 → 공유 → "홈 화면에 추가" 안내 그림을 보여 줌.
- 장점: 돈·스토어 필요 없음 · 지금처럼 index.html만 바꾸면 모두 바로 업데이트 · 구글 로그인 그대로 동작.
- 단점: **"파일을 주는" 방식은 아님**(주소를 주는 방식) · 아이폰은 여전히 수동.

### B. 안드로이드 APK 파일
1. **TWA (PWABuilder·Bubblewrap으로 포장)**
   - APK 안에서 실제 크롬이 게임 주소를 여는 방식 → 업데이트는 지금처럼 웹에서 자동 · 구글 로그인도 크롬이라 그대로 동작할 가능성이 높음.
   - 조건: 주소창 없이 뜨려면 **`https://dfdeer.github.io/.well-known/assetlinks.json`** 파일이 도메인 맨 위에 있어야 함. 지금은 `/AnimaRune/` 하위 주소라서 **`dfdeer.github.io` 이름의 저장소를 따로 만들거나, 개인 도메인을 사야** 함. (없으면 위에 주소창이 보이는 상태로 뜸)
   - 인터넷이 있어야 처음 열림(한 번 열면 sw.js 캐시로 오프라인 가능).
2. **Capacitor (게임 파일을 APK 안에 넣음)**
   - 오프라인에서도 바로 열림.
   - 단점: 앱 안 웹뷰에서는 **구글 로그인 팝업이 막힐 가능성이 높아서** 전용 플러그인(예: Capacitor Firebase 인증 플러그인)으로 바꾸는 작업이 필요함 — 확인이 필요해요. 업데이트마다 **새 APK를 다시 배포**해야 함(또는 APK가 웹 주소를 여는 방식으로 설정 — 그러면 TWA와 비슷해짐).
- 공통: 스토어 없이 파일로 주면 받는 사람이 **"출처를 알 수 없는 앱 설치 허용"**을 켜야 함. 플레이 스토어에 올리려면 개발자 등록(1회 25달러)이 필요함.

### C. 윈도우 실행 파일(.exe)
1. **Electron** — 설치 파일이 큼(대략 100MB 안팎). 만들기 쉬움.
2. **Tauri** — 설치 파일이 작음(수 MB~10MB대). 윈도우에 들어 있는 WebView2를 씀. 빌드에 Rust 도구가 필요함.
- 공통 주의: 구글은 앱 안에 박힌 브라우저에서의 로그인을 막는 경우가 있어서, **구글 계정 연결이 PC 앱에서 되는지 확인이 필요해요**(시스템 브라우저로 로그인시키는 방식이 필요할 수 있음). 게임 파일을 앱에 넣으면 Firebase 승인 도메인에 새 주소(예: `localhost`, `tauri.localhost`)를 추가해야 함.
- 참고: **A안(PWA)을 PC 크롬/엣지에서 설치해도** 시작 메뉴·바탕화면 아이콘이 생기고 창 하나로 떠서, 쓰는 느낌은 exe와 거의 같음.

### D. 아이폰
- 앱스토어·테스트플라이트 없이 **파일로 설치시키는 방법은 사실상 없음**(애플 개발자 등록 연 99달러 + 심사 필요).
- 현실적인 길은 A안(홈 화면에 추가)뿐.

## 3. 공통으로 신경 쓸 것
- **세이브 옮기기**: 웹·APK·exe는 저장 공간이 서로 따로라서, 옮길 때 **구글 계정 연결(서버 세이브)** 이나 세이브 내보내기/불러오기를 써야 함. 설치 안내에 꼭 적기.
- **업데이트 방식**: 웹 주소를 여는 방식(A, TWA, "주소 여는" Capacitor/Tauri)은 지금처럼 자동 · 파일을 넣는 방식은 버전마다 새 파일 배포.
- **버전 표시**: `APP_BUILD`로 이미 새 버전 알림이 있음 → 포장 방식에서도 그대로 쓸 수 있음.
- 이 작업 환경(클라우드 컨테이너)에 안드로이드 SDK·자바·Rust가 있는지는 아직 안 봤음 — 실제 빌드를 여기서 할 수 있는지 확인이 필요해요.

## 4. 추천 순서 (안)
1. **1단계 — A안**: 게임 안 "앱으로 설치" 버튼 + 아이폰 안내 그림. 하루 안쪽 작업, 모든 기기에 바로 효과.
2. **2단계 — 안드로이드 APK(TWA)**: `dfdeer.github.io` 저장소(또는 개인 도메인) 준비 → PWABuilder로 APK 생성 → "이거 다운해" 파일 배포. 업데이트는 웹 그대로라 관리 부담이 거의 없음.
3. **3단계 — PC**: 먼저 A안(크롬/엣지 설치)으로 충분한지 보고, 꼭 exe 파일이 필요하면 **Tauri로 게임 주소를 여는 방식**(설치 파일 작고 업데이트 자동). 구글 로그인 동작 확인이 먼저.
4. 아이폰: A안 유지.

## 5. 정해야 할 것 (사용자에게 물어볼 것)
1. 누구에게 배포하나 — 아는 사람 몇 명(파일 전달) vs 일반 공개(스토어)?
2. 플레이 스토어 등록(25달러) 할 생각이 있나? 아니면 APK 파일 직접 전달만?
3. 아이폰 쓰는 사람이 있나? (있으면 A안 안내가 꼭 필요)
4. `dfdeer.github.io` 저장소를 새로 만들거나 개인 도메인을 살 수 있나? (TWA 주소창 없애기에 필요)
5. PC는 exe 파일이 꼭 필요한가, 크롬/엣지 "앱 설치"로 충분한가?
6. 오프라인에서 처음부터 열려야 하나? (그렇다면 파일을 넣는 방식 — 대신 업데이트가 번거로움)
